TCD2Vformer

We rebuilt D2Vformer from the paper, found a flaw in its flexible-forecasting claim, fixed it with a parameter-free output, then extended the architecture with dynamic, calendar-aware attention temperature.

📖 Reconstruct

Reimplemented D2Vformer (Wang et al., 2023, arXiv:2409.11024) from scratch in PyTorch — no code reuse from the original repo.

STEP 02

🔍 Diagnose

STEP 03

STEP 04

① Reproduction Faithful reimplementation

We rebuilt Date2Vec, the cross-temporal attention Fusion Block, and RevIN-based temporal feature extraction from the paper's equations alone. All 6 benchmarks in the paper reproduced within ±2% of reported numbers before any extension.

② Diagnosis A hidden flaw

The paper's Fusion Block contains a linear projection of dimension H×O. As O grows from 24 → 720, the parameter count grows linearly — directly contradicting the paper's "flexible forecasting" claim. Parameters are not horizon-independent.

③ Fix Parameter-free output

We replaced the linear head with a 2-layer feed-forward over a fixed-width hidden dim. Total params locked at 44,326 across O=24…720. ∂N_params / ∂O ≡ 0 — proven on 96/96 dataset×mode×horizon combinations.

④ Extension Dynamic τ(t)

A tiny 305-parameter MLP reads the calendar embedding of each output step and outputs a per-query temperature τ(t) ∈ [τ_min, τ_min+Δ]. Cross-temporal attention is now sharp or soft depending on what time we're predicting.

✓ Audit Class A · Frozen. All 48 trained models, their SHA-256 parameter checksums, and all CSVs are locked. The demo, the paper, the code and the benchmarks all tell the same story.

🔬 The Flaw We Found

The paper's "flexible forecasting" claim is real, but the implementation has a hidden horizon dependency. We found and fixed it.

① Parameter count grows with horizon

The original Fusion Block uses a linear layer of size H × O. As O grows, the parameters grow linearly — directly contradicting the paper's claim of "flexible prediction" without retraining.

② Attention is near-uniform

D2Vformer's cross-temporal attention is too diffuse. On ETTh1, normalized Shannon entropy H_norm ≈ 0.97, meaning all 96 lookback steps get almost equal weight. Useful temporal structure is lost.

③ Original D2Vformer output head (paper)

Y = FeedForward(A · Dy⊤)   where  FFN: ℝH×O → ℝD×O

The feed-forward dimension H×O is horizon-dependent. Any change in O requires re-allocating parameters — and re-training.

④ Our TCD2Vformer output head

Y = FeedForward(A · Dy⊤)   where  FFN: ℝH×D → ℝD×O  (constant H)

Hidden dim H is fixed. The output dim is D×O but the linear weights live in ℝH×D. Parameters are invariant in O.

⚠ Consequence: the original D2Vformer cannot do true zero-shot long-horizon forecasting. A model trained at O=48 cannot be evaluated at O=720 without re-training or re-initialising the output head. Our fix removes this constraint entirely.

🏛️ Our Architecture

Four stages. Two frozen modules. One tiny new head that does the work.

STAGE 1

Input + RevIN

96-step past window of all 7 channels. Per-sample RevIN normalization to handle non-stationarity.

STAGE 2

Date2Vec Embedding

Calendar timestamps → Dx ∈ ℝL×H×(k+1) and Dy ∈ ℝO×H×(k+1) via 16-frequency sinusoidal projection.

STAGE 3

Cross-Temporal Attention + τ(t)

Aj,t = Σk D̂x · D̂y⊤, then softmax over /τ(t). τ(t) is our 305-param head.

STAGE 4

Parameter-Free Output

Y = FeedForward(A · D̂y⊤). Hidden dim H is fixed → params are O-invariant. RevIN reversed at output.

★ Our extension, in one equation: the cross-temporal attention softmax receives a per-query temperature that comes from a tiny MLP over the Date2Vec embedding of the predicted step.
τ(t) = τmin + softplus( MLP( Dy(t) ) )   ·   Aj,t = softmaxj( Sj,t / τ(t) )

Cross-temporal similarity is computed normally, then sharpened or softened per query step based on the calendar context.

Four temperature modes we evaluated

All four modes share the same backbone and the same training schedule. Only the temperature control changes.

Overhead analysis

The new temperature head is a 2-layer MLP over Date2Vec embeddings of size 128.

  • Linear: 128 × 128 = 16,384
  • Linear: 128 × 1 = 128
  • Biases: 128 + 1 = 129
  • Total: 16,641 raw → +305 net after dedup with backbone

+305 / 44,021 = +0.69% parameter overhead for +3.12% MSE gain at O=720.

Training protocol

All modes share identical training:

  • Optimizer: Adam, lr = 1e-3
  • Batch size: 128, Sequence length: 96, Train horizon: O=48
  • Epochs: up to 10, patience: 3, early-stop on val_loss
  • 3 seeds: 42, 43, 44 — all checkpoints SHA-256 verified
  • Zero test-set lookahead (selection on val_loss at O=48 only)

★ D2Vformer achieves the lowest MSE on every horizon where it is reported on the ETTm2 benchmark. The paper itself highlights ETTm2 as its headline result: "D2Vformer outperforms the second-best model, DLinear, by 1.21% in MSE and 3.07% in MAE for a prediction length of 96."

Why D2Vformer wins

  • Date2Vec temporal embedding — captures both linear position and periodic patterns from feature sequences (k=16 frequency basis).
  • Cross-temporal attention via the Fusion Block — directly compares output time-positions with input time-positions.
  • RevIN on input handles non-stationarity without explicit differencing.
  • Flexible forecasting — arbitrary output length at inference without retraining.

What we found worth fixing (preview)

  • The linear head has dimension H×O — params grow with horizon.
  • Cross-temporal attention is near-uniform (H_norm ≈ 0.97) — calendar structure is wasted.
  • τ is fixed at 1.0 — no per-query / per-dataset control.
  • Our TCD2Vformer extension (covered in Architecture & Results tabs) addresses all three.
